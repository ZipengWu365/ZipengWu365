# Prompt 变短了，你的 Agent 有没有做错事？

Zipeng Wu · 2026年10月27日 · 评测笔记

[English](2026-10-27-context-compression-checklist.md) · [全部文章](README.md)

评估上下文压缩，至少需要回答两个问题：删掉了多少输入，下一项任务还能不能正确完成。Token 数量能回答前一个问题，任务质量需要单独验证。

## 先看一个具体例子

下面是用于说明评测思路的**虚构历史**，不是真实用户记录，也不是任何方法的实测结果。

```text
09:00：重构时，把 /v1/orders 改成 /v2/orders。
09:10：取消改名。外部客户端仍然依赖 /v1/orders。
09:20：缓存清理已完成，分页测试还没写。
下一项任务：给接手的开发者写一份交接说明。
```

运行模型之前，就可以写下正确答案必须满足的条件：保留 `/v1/orders`；明确改名已取消；把分页测试列为待办；不能把缓存清理再次列为待办；关键判断能够追溯到原始记录。

压缩结果如果留下“准备改名”，却删掉了“取消改名”，就丢失了当前任务所需的区别。最后生成的交接说明可以很流畅，也可以完全错误。

这只是一个逻辑示例。它既不证明 TOMC 会失败，也不证明 TOMC 一定能通过。通过一个例子，只能支持该例子及其测试配置下的结论。

## 比较真正发出去的请求

先固定任务、读取模型及版本、指令、工具配置和判定标准，再比较完整历史、简单的最近历史基线和待测压缩方法。完整历史放不进模型上下文时，要说明处理方式，不能悄悄截断后仍称为完整历史。

保持系统指令和工具调用—结果关系完整。分别记录历史片段的 Token 数、压缩后历史的 Token 数和完整请求输入；额外包装文本也要计入对应口径。注明使用的 tokenizer，以及数值来自本地估算还是服务商返回的 usage。

从一个可检查的例子开始，再扩展到多条可公开的历史，覆盖决策修改、否定、未完成任务和无关信息。保留失败例子，报告任务数量和重复运行次数。

## 四项指标分开看

| 指标 | 应记录的内容 | 单独不能证明的事情 |
|---|---|---|
| 输入大小 | 历史、压缩后历史、完整请求输入 | 任务仍然正确 |
| 任务质量 | 预先定义的检查项、失败例子、判定方式 | 未测试场景中的可靠性 |
| 时间 | 预处理时间、端到端时间、重复次数 | 其他环境也能同样加速 |
| 成本 | 实际 usage、计费规则、缓存输入、输出和重试 | 能耗或碳排放下降 |

在相同统计口径下，原历史 Token 数大于零时，可以计算 `1 - 压缩后历史Token数 / 原历史Token数`。这个量应称为**历史 Token 减少比例**。没有额外证据，不能直接写成费用减少比例。

有缓存时，记录缓存条件；有重试时，把重试纳入工作流。没有计费证据，就把实际费用标为“未测量”。

## TOMC 在这里承担什么角色

[TOMC Memory](https://github.com/ZipengWu365/TOMC) 提供 CPU 上的上下文准备，以及显式保存、召回任务笔记的工具。当前公开文档区分了自行接入的 Python 请求流程，以及由客户端管理原生聊天和压缩的情形。安装 MCP 工具本身，不能证明每个模型请求都经过 TOMC。具体边界见[上下文归属说明](https://github.com/ZipengWu365/TOMC/blob/main/docs/context_ownership.md)。

用 `remember_memory` 保存一条笔记，再在使用同一本地数据库的新聊天里通过 `recall_memory` 找回，可以作为安装和持久化检查。这一步不等于完成了压缩性能评测。当前运行时的本地记录行为还受版本和设置影响，测试敏感材料前应阅读[当前文档](https://github.com/ZipengWu365/TOMC#first-run-tomc)。

仓库里的[已记录实验](https://github.com/ZipengWu365/TOMC#measured-savings)各有适用协议。本文没有新增性能结果、客户端兼容性验证或节能估算。

## 第一次参与，做一件小事就够了

使用一条虚构笔记，按[首次运行反馈帖](https://github.com/ZipengWu365/TOMC/issues/11)测试保存与召回，说明系统、客户端版本、TOMC版本、卡在哪一步，以及是否出现真实工具返回。成功和失败都可以反馈，不需要先跑大规模 benchmark。

不要上传密钥、私人对话或笔记数据库。

压缩后先问一个具体问题：**下一位助手还能找回哪些决策、约束和未完成工作？**
